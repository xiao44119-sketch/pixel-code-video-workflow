用故事板做 coding 视频 · 使用教程

导演会话：负责看完整片、拆依赖、分批次和验收。执行会话负责实现画面。

这份教程只讲实际使用方法：怎么保护母版、怎么规划会话、怎么给短提示词，以及什么时候继续当前会话或换新会话。

1. 开始前：永远先复制母版

最重要的规则：不要直接在“skill 母版”里做项目。母版要一直保持干净，当前视频只在复制出来的副本里制作。

保留原始母版，不放故事板、不放项目素材，也不写某一部视频专用的代码。

复制整个母版文件夹，给副本改成当前视频的名字；后续所有操作都在这个副本里进行。

把故事板放进副本的 .media/storyboard/，然后在副本目录运行 npm run dev。

以后做新视频，再从干净母版复制一份。只有经过项目验证、对所有视频都通用的经验，才回写母版，而且只做最小迭代。

母版 = 可重复使用的规则和工程骨架；副本 = 当前视频的工作现场。

2. 先开导演会话，再开执行会话

导演会话贯穿整部视频。它第一次读取 skill，查看所有故事板，决定共享主体、依赖关系、并行批次和每个执行会话负责哪些镜头。不要拿到镜头就立刻一个镜头开一个对话。

3. 导演会话：先把整片拆成批次

先把skill文件

第一次提示词

先读 skill/SKILL.md。我要用这个母版副本制作视频，故事板在 .media/storyboard/。先不要写代码。请看完全部故事板：按共享主体分组，标出镜头依赖；为连续形变镜头比较实现方案；列出图片素材及画面显示尺寸。再按依赖规划执行批次：每个执行会话优先安排 2–3 个镜头，指出哪些批次可并行、哪些部分必须等上一镜尾帧。填好 STORYBOARD.md、RENDER_STRATEGY.md 和 timeline.json，只把分组表、素材清单和执行批次计划给我确认。

关键帧通过后就给以下提示词

静态关键帧全部通过。现在只在这些已通过端点之间制作确定性补间和摄影机运动，不改变任何端点构图;完成后输出hyperframs预览。

导演怎么分批

同一个主体连续存在或形变的镜头放在同一组，尽量交给同一个执行会话连续完成。

强依赖上一镜尾帧的部分按顺序做；如果只等待入场位置，主体场景和内部动画可以先做，最后再接桥。

独立地点、背景、透明素材和不依赖前镜构图的镜头可以同时开多个会话。

默认每批 2–3 个镜头；特别复杂的镜头可单独一批，简单且共用渲染器的镜头可放满 3 个。

并行会话不能同时改 timeline.json、共享母场景源文件或已经通过的镜头。

4. 执行提示词由导演会话生成

不要照抄固定模板

执行会话的提示词必须由导演会话根据当前项目现状生成。导演要先看本批故事板、上一镜通过尾帧、共享主体、已锁定素材、渲染方案、可写文件和最新 HANDOFF，再决定这一次该说什么。教程中的句子只能帮助理解流程，不能直接当成所有镜头通用的执行提示词。

正确做法是：每次准备新执行批次，先回到导演会话报告最新进度，由导演为这一批生成一段可直接发送的提示词。提示词长短和内容由镜头复杂度决定，不使用固定格式。

向导演索取新执行会话提示词

请根据最新 STORYBOARD.md、timeline.json、HANDOFF.md 和本批相关故事板帧，为【批次/镜头】生成执行会话启动提示词。请写明这个镜头特有的主体、运动或形变、必须复用的通过内容、允许修改的文件、依赖关系和验收输出；删除无关背景。

同一执行会话继续下一镜

把当前镜头的验收结果和下一镜告诉导演，让导演判断能否留在原执行会话，并生成下一条短提示词。它应引用刚通过的尾帧和锁定项，不重复整套规则。

导演生成提示词时必须考虑

当前执行会话已经完成几个镜头、上下文是否仍健康；本镜是否依赖上一镜真实尾帧；哪些主体、素材和镜头已经锁定；本镜独有的运动、形变、摄影机和验收关键帧；哪些文件允许修改、是否与并行会话冲突；本次只应交付接触表、预览还是成片。

不要重复读 skill：导演给同一执行会话的续作提示词，不应要求它重新读取 skill 或重复项目历史；只补充新镜头的必要信息和本次验收结果。导演写的是针对当前镜头的施工指令，不是套用模板。

6. 验收只看画面，不看报告

阶段

执行会话只需交付

静态

一张包含故事板关键帧的接触表 + 等待验收

动画

一个可拖动预览 + 等待验收

修正

修正后的帧或预览 + 一句话

最终

总预览或视频 + 时长和输出路径

默认不要 validation-report、AUDIT_REPORT、文件清单、交付说明、身份/Mesh/粒子报告、逐帧哈希、像素差异、重复渲染、反向拖动验证或多套接触表。它们不会帮助你判断画面，只会增加时间、文件和上下文。

停止生成报告和审计产物。只完成当前画面，并给我一张验收帧或可拖动预览。

先判断是素材坏了，还是素材用错了

尺寸、位置、裁切、摄影机、颜色和特效不对时，只改对应参数。已经通过的素材默认锁定；只有你明确说“素材本身不行”，才允许重新生成。

7. 换会话时，只写最小交接

HANDOFF.md 是当前状态，不是工作日志。建议少于 100 行，只保留当前批次、已锁定项、正在使用的文件、未解决问题、短句式否决项和下一步。

结束当前执行会话

本批次结束。更新 HANDOFF.md，只保留当前有效状态、已锁定镜头/素材/接口、当前文件、未解决问题、已否决方案的一句理由和下一步。不要写长篇复盘、报告、完整历史或文件清单。完成后只报告当前状态；下一批执行提示词由导演会话生成。

回到导演会话生成下一条

把最新 HANDOFF.md 和本批验收结果交给导演会话，并说：请重新检查剩余依赖、已锁定内容和可并行任务，为下一个执行会话生成最适合当前镜头的提示词，不要沿用上一批的通用模板。

8. 所有镜头通过后再拼接

所有执行批次已经通过。按 timeline.json 拼接已通过合成，不要重构或修改已通过镜头。完整播放一次，检查镜头接缝和总时长，运行一次 check，然后只给我总预览等待确认；不要生成审计报告。

总预览确认后，再说：

总预览通过。现在渲染成片，只告诉我视频时长和输出路径。

也可以在Hyperframes预览界面点右上角的Export导出，这样不用消耗codex的token，不过渲染会很慢，要等挺久才能导出视频

9. 卡住时怎么说

位置或尺寸连续三轮还不准

把当前画面的必要位置、尺寸和角度抽成最小滑块面板让我调；不要加拖拽控制点。

预览打不开或某一帧异常

只检查与这个问题相关的代码、控制台错误和这一张问题帧，修好后给我结果。不要生成审计脚本或报告。

方向跑偏

先别改代码。用一段话说明你准备改什么、复用什么、不会动什么，我确认后再继续。

一眼看懂整套流程

保留干净母版 → 复制副本 → 导演看完整片并按依赖分组 → 规划每个执行会话 2–3 镜 → 并行做独立素材和场景 → 每镜先静态、后动画 → 会话健康就继续，过长才交接 → 所有镜头通过后拼接 → 一次检查 → 渲染。
